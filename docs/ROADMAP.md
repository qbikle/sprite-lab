# sprite-lab Roadmap

**Vision:** the pixel-art + animation editor you reach for instead of Aseprite for pixel
work on the web. Cozy-retro but professional — ergonomics beat theatre. No accounts, no
cloud, files in files out. Zero runtime deps, strict TS, real architecture
(see `ARCHITECTURE.md`).

The original 7-phase single-file plan (v1) is superseded by the wave plan below. v1 is
RETIRED as of Wave 5 (labeler parity reached); `legacy/sprite-lab-v1.html` stays only as
a historical reference.

## Design principles

- **Files in, files out.** Autosave (localStorage/OPFS) is scratch, never the source of truth.
- **The document is honest.** `.sprite` is a convenience envelope over PNG-expressible pixels + JSON metadata; nothing held hostage.
- **Fast to open, fast to fix.** The "one broken frame" loop (open → spot → fix w/ onion → export) stays under a minute.
- **Ergonomics beat theatre.** Keyboard-first, 60fps always, crisp pixels at every zoom.

## Gotcha ledger

- Author `display` on styled overlays defeats the UA `[hidden]` rule — pair with explicit `[hidden] { display: none }`.
- Canvas pointer→pixel math must correct for `clientLeft/Top` (border widths).
- localStorage is per-origin: two ports = two edit buffers. Solved properly by project files (Wave 5).
- Frame auto-detection is alpha-based: opaque-background sheets need background-color keying (Wave 5 slicer option).
- Animated WebP encode relies on `OffscreenCanvas.convertToBlob('image/webp')` — Chrome-family only; Safari path falls back to GIF.
- `noUncheckedIndexedAccess` on: index access returns `T | undefined` — design APIs to avoid `!`.
- Inputs swallow single-key shortcuts (typing guard): any commit-on-Enter input MUST `blur()` after commit or the next hotkey dies in the input.
- Playwright pages default to `colorScheme: 'light'` — dark-theme screenshots need an explicit `colorScheme: 'dark'` context (main.ts falls back to `prefers-color-scheme`).
- Node ESM resolves imports from the *script file's* location, not cwd — throwaway scripts importing devDeps must live inside the repo.
- `ImageData` can legally wrap a shared `ArrayBuffer` → zero-copy composite upload (`putImageData` + dirty-rect args). Compositor relies on this.
- Every state that panels display must have a bus event fired from EVERY writer — `viewport.setDocSize` forgot `camera:changed` after refit and the statusbar zoom went stale.
- Selection/float commands close over a `SelectionHost` accessor object whose setters emit the bus events — the one sanctioned impurity in the command layer (undo-across-everything beats purity here).
- Midpoint ellipse: use Zingl's rect-fitted variant — even-width/height boxes have half-integer centers the classic integer-radius form can't rasterize; filled ellipse must derive spans from the SAME plotter or fill ≠ superset of outline.
- Mode-toggle tiles must never render empty in their off state — an empty tile reads as a broken button; show the glyph dimmed.
- While a float is live, suppress the underlying selection's marching ants — two outlines read as a bug.
- vitest and playwright share `tests/` — vite.config needs `test.include: ['tests/unit/**']` or vitest chokes on playwright specs.
- SVG icons inside flex buttons can lay out at width **0** (flex-shrink on the svg item) while DOM inspection shows correct attrs — `.sl-mini-btn svg { flex: none }` fixes it; screenshot-verify icons, never trust attr presence.
- Rapid-fire slider inputs must not each commit a command — replace-last coalescing in the app wiring (undo+commit within a drag window) keeps one history entry per drag.
- Structural commands allocate ids ONCE (first apply, cached) — re-allocating on redo corrupts cel keys after undo/redo cycles.
- Playback: exactly one `playback:changed` emitter (the Player); everyone else syncs from the bus, or events double-fire.
- Icons render ONLY at integer multiples of the 16 grid (16/32) — fractional sizes (10/12/14) blur `crispEdges`. Buttons grow to fit the icon, never the reverse.
- Paired glyphs (undo/redo, prev/next, up/down, x/y) are DERIVED via mirror/flip/transpose in `icons.ts` — hand-copying a mirror drifts; the unit test pins the derivations.
- Base shell button CSS must sit at zero specificity — `:where(.sl-shell) button` — or its padding beats single-class component rules (`.sl-mode-btn { padding: 0 }` was dead, squeezing mode-tile content to 8px).
- All shell-button svgs get `flex: none; display: block; pointer-events: none` globally — flex-collapse, baseline offset, and svg-overhang click-stealing are all real, all screenshot-invisible in DOM attrs.
- Undoable palette/doc mutations emit ONLY `doc:changed` — panels listening for a convenience event (`palette:changed`) go stale on undo/redo. Subscribe panels to `doc:changed` scopes; convenience events are for non-command state.
- e2e must assert the DOM, not just `__lab` — the stale-palette bug lived through a whole wave because specs read editor state directly.
- `convertToBlob({type:'image/webp'})` is LOSSY by default — always pass `quality: 1` for pixel art (Chromium then emits lossless VP8L).
- OPFS `createWritable` commits only on `close()` — a tab-kill mid-write leaves the OLD file. Any dual-store persistence needs a stamp + newer-wins restore, and `beforeunload` alone never fires on iOS (add pagehide/visibilitychange).
- UI "replace-last" coalescing must verify identity via `History.peekUndo()` — index+time windows alone undo innocent bystander commands.
- Capture-phase modal handlers must swallow ALL non-typing keydowns, not just Escape — global single-key shortcuts stay live behind dialogs otherwise.
- An open native-style menu needs Enter/Space `stopPropagation` — a global Enter shortcut's `preventDefault` cancels the focused item's activation click.
- `lostpointercapture` ≠ pointer gone — treating it as an "up" deletes a still-down finger from the touch map and dissolves a forming pinch. Cancel that pointer's gesture only; never touch the multi-touch map.
- Pen state must clear on WINDOW-level pointerup — pen ups can land off-canvas (down never started a draw); canvas-only listeners leave touch input dead forever (palm rejection stuck on).
- First-run detection needs a marker beyond localStorage (cookie too) — e2e's `localStorage.clear()+reload` would otherwise turn every old spec's boot into a demo boot.
- Deploys must bump `VERSION` in public/sw.js or clients keep the old shell cache (hashed assets self-invalidate; the shell doesn't).
- Hosting under a subpath needs Vite `base` + a relative SW registration path — everything currently assumes root.
- Stacked modals: `stopPropagation` never silences other listeners on the SAME target (window) — every open modal's capture handler still fires. A module-level stack with only-the-top-reacts is required or one Esc closes everything.
- Two capture listeners on the same target fire in registration order — registering a `?`-close handler BEFORE `modal.open()` is how the cheat sheet closes on `?` while the modal swallows everything else.
- Doc DIMS can change under session state (ResizeCanvas + its undo/redo): doc-sized buffers (stage, selection mask) keyed to old dims index with new-width math and commit scrambled pixels — drop them on `doc:changed {kind:'all'}` via length checks; app resyncs compositor+viewport on the same event with a dims comparison ('all' also fires for SwapColors).
- cmd+V is TWO events: the `mod+v` shortcut (internal pixel paste) and the native `paste` event (system-clipboard import) fire on one keystroke — the import path must yield when an in-app clipboard exists or a stale screenshot clobbers a deliberate paste.
- CDP `Input.dispatchMouseEvent` is the only way to compose modifier keys onto a wheel event in Playwright (modifiers bitmask: Alt=1, Ctrl=2, Meta=4, Shift=8).
- Playwright transpile can mangle in-page dynamic `import()` — pass string bodies to `page.evaluate` for vite-served module imports.
- Screenshots taken immediately after opening a fading overlay catch it at opacity ~0 and look like "the modal never opened" — settle ≥250ms past the transition before shooting; e2e clicks pass regardless (opacity:0 still counts as visible), so only screenshots reveal it.
- Keyboard UI INSIDE a Modal (roving tabindex, arrow nav) needs its own window-capture listener registered BEFORE `modal.open()` — the Modal swallows all non-typing keys at capture, and same-target capture listeners fire in registration order.
- Playwright `download.path()` is extensionless — `saveAs` with the real extension before re-feeding any picker that routes by filename.
- `ui/modal.ts`'s DEV harness touches `window` at module scope — vitest (node env) needs `globalThis.window` aliased before a dynamic import of anything that pulls it in.
- The modal's 120ms slide-in moves drag targets — e2e that measures boxes inside a fresh modal must wait for `transform === 'none'` first.
- A live preview panel must own a DEDICATED Compositor — sharing the viewport's thrashes its single-frame composite cache every preview tick (full re-flattens on the main canvas).
- Direct-drive spec shims (module-import mounts of panels awaiting app wiring) MUST be deleted at integration — a wired app plus the shim mounts the panel twice and strict-mode locators explode.
- The left toolbar rail overflows viewports under ~960px tall (undo/redo scroll below the fold; rail is overflow-y auto). Known cosmetic debt, revisit if tools grow again.
- `**/`-style glob literals inside a spec's block comment terminate the comment — playwright then parses garbage ("v1 is not defined").
- Cross-origin `page.route` fulfills still meet CORS preflights — point the arcade client at same-origin via its `sprite-lab:v2:arcade-api` localStorage override and intercept `/v1/sl/**` relative paths instead.
- The arcade server clamps list `limit` to 1–30 — never ask for more.
- Render's per-key env-var API PUT does NOT trigger a redeploy — POST /v1/services/{id}/deploys after setting, or the process keeps the old env.
- Private-mode browsers regenerate the arcade anonId per session (no localStorage) — budgets then key mostly off IP; by design.
